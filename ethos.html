2 DATA MATURITY ARCHITECTURE

Layer 5: Delivery Role-Based Access

Executive aggregates, Dean/program views, and student-success operational views (authorized roles only).

Layer 4: Certification Certified Views

Canonical SQL views with documented definitions (cohort, census timing, risk flags, fill rate logic).

Layers 1–3: Integration & Staging

Ethos API staging → validation (orphan checks, term alignment) → canonical mapping (IDs, programs, courses).

Governance: No analytics runs against production transactions. Dashboards point exclusively to Layer 4 Certified Views with controlled refresh and audit checks.

Security

FERPA-aligned. Small-cell suppression (<5) for published aggregates.

Validation

Orphan checks, term coverage checks, and census-aligned definitions.

Identity

PII restricted; staff access via role-based security + audit trail.
